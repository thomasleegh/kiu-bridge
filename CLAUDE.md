# 橋 Kiu — Cantonese ↔ Mandarin Bridge App

Personal PWA (a "my own Duolingo"). User is a heritage Cantonese *listener* (passive, never spoke it) learning to activate Cantonese speaking and learn Mandarin in parallel. Sound/romanization first (Jyutping + Pinyin); characters are secondary, shown small/muted after reveal.

## Stack & files
- Single-file app: `index.html` (~90KB, vanilla JS, no build step, no dependencies).
- `manifest.json`, `sw.js` (stale-while-revalidate; bump `CACHE_NAME` when shipping — the page reloads itself once when a new version takes over), `icon-192.png`, `icon-512.png`.
- `scripts/e2e.mjs` — browser regression suite (see the loop rule); `scripts/test-lookup.mjs` — dictionary ranking tests.
- `dict.json` (~3 MB, ~1.2 MB gzipped) — the offline dictionary, generated by `scripts/build-dict.mjs` (see "Offline Add").
- Deploy: Netlify (static, publish dir = repo root). Same URL = same localStorage = progress preserved. Target device: iPhone Safari → Add to Home Screen.

## Hard rules
1. **One file, one version.** `index.html` auto-detects its environment: `const IS_STANDALONE = typeof window.storage === 'undefined'`. If standalone, it installs a localStorage polyfill (`kiu_` prefix) and registers the service worker. Never fork or hand-patch a "standalone copy" — an earlier bug came from a polyfill leaking into the in-chat build and wiping progress.
2. Storage API used everywhere: `window.storage.get/set/delete/list` (async, returns `{value}`). Keys: `progress`, `meta`, `customWords`, `pendingAdds`, `apiKey` (standalone only).
3. All buttons need `-webkit-appearance:none` + explicit height (iOS Safari otherwise changes tab heights).
4. Keep romanization primary; characters secondary styling. Cantonese characters Traditional, **Mandarin characters Simplified** (user's rule, 2026-10-15): all Mandarin goes through `toSimp()` (built-ins at startup, saved words on load, dictionary results, AI replies, `addCustomWord`). The table is the `<simp-map>` block, generated by `scripts/build-simp.mjs` from dict.json — rerun it after rebuilding the dictionary.
5. Test on mobile width (390×844). Playwright + Chromium works for headless checks.

## Every feature: close the loop, prove it, keep the test (user's rule, 2026-10-05)
Why: the first offline-Add release let you save a word "to translate later", but with no API key nothing
could ever translate it, iOS didn't fire `online` when the app resumed, and the item sat there forever
with no explanation. The browser tests only checked the first half (it got queued), and a 219px-tall
button slipped through because nobody measured it. So, for every new feature or change:
1. **Trace every path to its end state.** For anything that waits, saves for later, syncs, or depends on
   network/API key/permissions: list each state (online/offline, key/no key, app resumed from background,
   API error then recovery, duplicate input, data saved by an older version) and make sure each one
   either finishes or shows the user exactly why it hasn't and what fixes it. No silent dead ends.
2. **Don't rely on one trigger.** iOS home-screen apps often miss `online`; re-check on launch,
   `visibilitychange` (app back in front), and whenever the missing piece arrives (dictionary loaded,
   key saved).
3. **Test the whole loop in `scripts/e2e.mjs`** (Playwright, 390×844, Anthropic API mocked): write the
   test first, watch it fail on the old code, then fix. Add the new cases permanently — the file is the
   regression suite. Measure layout you touch (sizes, overflow), don't eyeball it.
4. **Before pushing:** `node scripts/test-lookup.mjs` and `node scripts/e2e.mjs` both all passing; bump
   `CACHE_NAME` in `sw.js`.
5. **Wrap-up** lists what changed, what to tap on the phone, and what the tests covered vs. what only a
   real iPhone can confirm.

## Data model
- `VOCAB` (65 built-ins; cats: Greetings, Pronouns, Family, Food, Time, Verbs, Phrases): `{id, cat, eng, cChar, cRom, mChar, mRom, same, cLit?, mLit?, note?}`
- `CONVOS` (4 dialogues), `SCENARIOS` (3 role-plays: convenience store, market, mall)
- `customWords[]` — user-added via Add/Scan; cat `Custom` (words) or `Phrases`. All three add paths go through `addCustomWord()`. Stored oldest→newest; the Add tab's "Your words" shows the 20 newest, newest on top (the Library has all).
- `pendingAdds[]` — text saved with the AI button while offline. `processPendingAdds()` resolves each one: with an API key → AI once online; without → the offline dictionary's best match. Anything it can't resolve keeps a visible reason (`pendingReasons`: waiting for internet / no offline match, needs a key / AI failed, will retry). Runs on launch, dictionary loaded, `online`, `visibilitychange`, and key saved. Never adds a word that's already saved or built in.
- `progress[id] = {status:'new'|'learning'|'known', shakyCount:n}`; `shakyCount` increments on every "Still shaky" and persists after graduating to Known. Known/Learning lists sort by `shakyCount` desc.
- `meta = {streak, lastPracticeDate}`

## UI structure
- Home: stats row (Known / Learning — tappable, open the Library filtered to that status via `state.focus`), secondary tabs **Add | Scan** (~40px), primary tabs **Words | Phrases | Speaking** (~56px). All share one container/gold active style.
- Top bar: gear (Settings), book (**Library**), streak.
- Library (`renderProgressList`/`refreshLibrary`, view `progressList`): every word in one alphabetical list (ignoring leading to/the/a), live search over English, Jyutping, Pinyin (tone marks/numbers ignored) and characters, a coloured status dot per word (green known, gold learning, grey new), "N× shaky" when >0, and All/Known/Learning/New chips with counts. The home Known/Learning stats open it pre-filtered, so their numbers match the list (tested).
- Words/Phrases: Learn (8 cards: reveal → Got it / Still shaky), Quiz (meaning→sound MCQ), browse by category.
- Speaking: pick language → scenario → NPC line (romanization + TTS) → mic (SpeechRecognition `zh-HK`/`zh-CN`) → transcript for self-assessment, "Need help" shows model answer. No auto-scoring.
- Settings: in Claude shows "no setup needed"; standalone shows API-key input.
- Palette: `--ink:#14161B --surface:#1D2027 --paper:#EDEAE1 --canto:#E8543E --mando:#45A395 --gold:#D8A657`. Fonts: Noto Serif TC (chars), Space Grotesk (UI), IBM Plex Mono (romanization). Bridge cards: Cantonese rail red on top, Mandarin rail teal below; `lit. "..."` italic subtext only when literal meaning differs.

## Offline Add (dictionary) — built 2026-10-04
User's ask: offline-capable, quick-loading basic translation + adding to the personal dictionary.
- **Add works with no internet.** Typing shows live results (in place, no re-render, so the keyboard stays up): built-in/saved words first (`searchAppWords`), then `OfflineDict.search`. Each result has one-tap Add. "Translate with AI" stays as the second option; offline it becomes "save to translate later" (`pendingAdds`). Scan still needs internet (says so offline).
- **Startup is never blocked:** `dict.json` is fetched ~400 ms after first render (standalone only) and precached by `sw.js`, which serves it cache-first (it only changes with `CACHE_NAME`). Google Fonts load via a non-blocking `<link media=print onload>` (the old `@import` held the page until Google answered and hung offline); `sw.js` caches the font files (opaque responses).
- **How the lookup picks words** (the `<offline-dict>` block in index.html):
  1. `scripts/canto-mando-pairs.txt` — ~120 hand-checked everyday words where Cantonese and Mandarin differ (eat 食/吃, look 睇/看…), plus a few same-word pins where the data's top pick is off (teacher 老師, phone 電話). Checked first. Add to it when a common word comes out wrong; pin a reading with `字 [reading]`.
  2. Otherwise: best CC-CEDICT/CC-Canto entry by English-sense match + Mandarin frequency (jieba) + spoken-Cantonese frequency (HKCanCor), shown as the same word with Jyutping and Pinyin — true for most vocabulary. Frequency alone can't do this for divergent words (噉 has a rare "to eat" reading), which is why the pairs list exists.
  3. Chinese input: exact headword, else word-by-word (each known word swapped to the other language, e.g. 我想食飯 → 我想吃飯), labelled a guess; ambiguous single characters (走 都 好 飯…) are never swapped.
- **Tests:** `node scripts/test-lookup.mjs` (evals the shipped block against dict.json, ~40 cases incl. divergent words and sentences). Run it after touching the block, the pairs list or the build.
- **Rebuild:** see README. Sources: CC-CEDICT (CC BY-SA 4.0), CC-Canto (CC BY-SA 3.0), HKCanCor (CC BY 4.0), jieba (MIT), to-jyutping (BSD-2); credited in Settings.

## Claude API features (Add + Scan)
- Add tries the offline dictionary first (above); AI is the fallback. Both call `https://api.anthropic.com/v1/messages` with model `claude-sonnet-4-6` via `apiHeaders()`.
  - In Claude artifact sandbox: no auth headers needed.
  - Standalone: user's own key from Settings, sent with `x-api-key`, `anthropic-version: 2023-06-01`, `anthropic-dangerous-direct-browser-access: true`. Errors: `nokey`, `badkey` (401/403), `network`, `api`, `parse`, `incomplete`.
- `translateEntry(eng)` → JSON `{type, cChar, cRom, mChar, mRom, lit, note}`; parsing uses first `{`…last `}` extraction (tolerant of stray text).
- `scanImageForText(base64)` → image resized client-side to 1024px JPEG, returns JSON array.
- **Known security tradeoff:** key lives in browser localStorage. Fine for personal use. If this goes beyond personal use, replace with a tiny serverless proxy (e.g. Netlify Function) holding the key server-side.
- TTS: `SpeechSynthesisUtterance`, `zh-HK` / `zh-CN`, best-voice pick with toast fallback.

## Previously fixed bugs (don't regress)
- Polyfill leaking into in-chat file (progress reset on reopen).
- Stale error toast after successful retry (`hideAudioNote()` on new attempt + on success).
- Fragile JSON parsing.
- iOS tab height mismatch (see rule 3).
- Render-blocking Google Fonts `@import` (slow start, offline hang) — keep fonts non-blocking.
- Save-for-later queue that could never finish without an API key / missed `online` on iOS (see the loop rule).
- Unsized SVG icon in `.btn-secondary` made the AI button 219px tall — button icons are 16px.
- Speaker buttons silent on iPhone: Safari drops `speak()` right after `cancel()` — only cancel when something is playing; buttons pulse while playing, explain when nothing starts (silent switch/volume/voice), ~44px tap area.
